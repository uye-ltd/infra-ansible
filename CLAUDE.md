# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Install required collections (once)
ansible-galaxy collection install -r requirements.yml

# Run a playbook
ansible-playbook -i inventory/hosts.yml playbooks/<name>.yml

# Dry-run (check mode — no changes applied)
ansible-playbook -i inventory/hosts.yml playbooks/<name>.yml --check --diff

# Run only specific tags
ansible-playbook -i inventory/hosts.yml playbooks/<name>.yml --tags <tag>

# Lint everything
ansible-lint

# Lint a single file
ansible-lint playbooks/<name>.yml
```

## Repository layout

```
playbooks/          # Thin orchestration entrypoints — import roles, set play vars
  templates/        # Templates used by local (localhost) playbooks (e.g. WireGuard client configs)
roles/
  common/           # Package updates, base tools, timezone, hostname
  users/            # User accounts, SSH keys (`ssh_public_keys` list), sudo grants
  ufw/              # Firewall: default deny-in, allow-out, configurable rule list
  docker/           # Docker CE install (Debian + RedHat), docker group membership
  git/              # Clone/pull repos (public HTTPS + private SSH via GitHub App token)
  caddy/            # Caddy web server: apt repo, Caddyfile template, UFW rules, HTTPS via ACME
  edge/             # infra-edge checkout, Certbot DNS credential, renewal, cutover and rollback
  wireguard/        # WireGuard server: install, sysctl, wg0.conf, UFW rules (51820/udp + 53 from VPN subnet), explicit iptables FORWARD/MASQUERADE, wg-quick service, dnsmasq
  filebrowser/      # FileBrowser binary, systemd unit, JSON config
  storage/          # Mount block devices via ansible.posix.mount, persist in /etc/fstab
  runner/           # Self-hosted GitHub Actions runner: ghrunner user, AppArmor, systemd-managed egress policy, repo clone, .env, GHCR login
inventory/
  hosts.yml         # Static YAML inventory
  group_vars/       # Variables scoped to host groups
  host_vars/        # Variables scoped to individual hosts
secrets/            # Gitignored — generated by keygen.yml, never committed
  wireguard.yml     # Server private key + all peer keys (loaded by wireguard role via include_vars)
  clients/          # Per-device WireGuard .conf files, importable or scannable as QR
requirements.yml    # ansible.posix + community.general collections
```

Each role follows the standard layout: `tasks/`, `handlers/`, `defaults/`, `vars/`, `meta/`, and `templates/` where needed.

## Architecture

**Playbooks vs roles:** Playbooks in `playbooks/` are thin orchestration files that import roles and set play-level vars. All reusable logic lives in roles.

**Multi-OS support:** Tasks that install packages must branch on `ansible_os_family` (Debian vs RedHat) or use `ansible_pkg_mgr`. Use `include_tasks` with `when:` rather than inline conditionals on every package task.

**Secrets:** Two patterns are used depending on the role:

- **WireGuard** — keys live in `secrets/wireguard.yml`, generated once by `playbooks/keygen.yml` and loaded into the role via `ansible.builtin.include_vars`. Never commit this file. Back it up externally.
- **Everything else** — secrets are pulled at runtime from the local `.env` file (via `lookup('env', ...)` with a `regex_findall` fallback that reads `.env` directly) or from an external secrets manager. The `.env` file sits one level above the repo root and is gitignored. Current secrets used this way:
  - `FILEBROWSER_ADMIN_PASSWORD` — FileBrowser admin password
  - `ANDROID_SSH_PUBLIC_KEY` — ed25519 public key for Android SSH access (Termius); added to `ssh_public_keys` list for the user in `group_vars/all.yml`
  - `CLOUDFLARE_API_TOKEN` — Cloudflare API token (Zone:DNS:Edit + Zone:Read for `uye.rocks`); used by Caddy for the ACME DNS-01 challenge. Delivered to the caddy service via `/etc/caddy/caddy.env` and a systemd `EnvironmentFile` drop-in, and referenced in the Caddyfile as `{env.CLOUDFLARE_API_TOKEN}`.

## Conventions

- **Tags:** Every role is tagged with its own name (e.g. `tags: docker`); within a role, group related tasks under sub-tags (e.g. `tags: docker,install`). This allows targeted runs.
- **Handlers:** Service restarts and reloads go in `handlers/main.yml` and are triggered with `notify:`. Never call the `service` module directly in tasks for restarts. Note: the `wireguard` role handler uses `state: restarted` (not `wg syncconf`) so that PostUp iptables rules are re-applied on every config change.
- **Defaults vs vars:** Put all tuneable knobs in `defaults/main.yml` (lowest precedence, safe to override). Put role-internal constants that should never be overridden in `vars/main.yml`.
- **Idempotency:** Every task must be safe to re-run. Avoid `command`/`shell` unless `creates:`, `removes:`, or `changed_when:` is set.
- **Collections:** Use FQCN for all modules (e.g. `ansible.builtin.apt`, `community.general.ufw`). Required collections are declared in `requirements.yml`.
- **check_mode:** Tasks that must run even during `--check` (e.g. read-only probes like `which wg`) should set `check_mode: false`. Tasks with side effects (key generation) are intentionally skipped in check mode.
- **Firewall ownership:** The `ufw` role owns only the base rules in `ufw_rules` (SSH by default). Each service role opens its own ports directly via `community.general.ufw`. The `ufw` role does **not** reset the firewall — re-running `bootstrap.yml` will not close ports that caddy, wireguard, or filebrowser have opened. To add ports that the `ufw` role manages, extend `ufw_rules` in `host_vars/<host>.yml`.
- **User group membership:** Always use `append: true` on `ansible.builtin.user` tasks that set `groups:`. Without it the module replaces the user's full group list, silently removing memberships added by other roles (e.g. the `docker` group added by the docker role).
